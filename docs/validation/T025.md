## Requirement

> T025: Add a benchmark helper (`scripts/benchmark.py`) that times a
> `transcribe` run against a given video and prints elapsed time
> (SC-002/SC-006, quickstart.md Scenario 8), and, given a small labeled
> reference corpus (sample videos + their known-correct transcript text),
> reports rough transcript-accuracy and subtitle-timing-sync percentages
> against that corpus. Note: SC-003 ("judged by a reviewing user") and
> SC-004 ("perceived by a viewer") are spec.md's own human-judgment
> criteria, not automatable pass/fail checks — this script gives `qa` a
> concrete number to anchor that judgment against, it does not replace it.

This decomposes into 7 checkable sub-requirements:

1. `time` mode runs a real `transcribe` pipeline against a video and
   prints a sensible elapsed time and realtime ratio (SC-002/SC-006,
   quickstart.md Scenario 8).
2. `corpus` mode, given a real labeled reference corpus, reports
   transcript-accuracy and timing-sync percentages (SC-003/SC-004
   anchors, not pass/fail verdicts).
3. Review-round-1 fix #1 (`load_corpus` type validation) actually rejects
   malformed manifest fields cleanly (`Error: ...`, exit code 1), not with
   a raw traceback.
4. Review-round-1 fix #2 (README's `tests/fixtures/benchmark_corpus.json`
   example) points at a real, working file.
5. `tests/unit/test_benchmark.py` passes.
6. `tests/integration/test_benchmark.py` passes.
7. No regressions in the broader suite (`pytest -q`).

SC-002/SC-006 target (~2x real time, i.e. processing <= half the video's duration): within target (1.5s elapsed vs. 1.7s target).

Spot-checked the math myself against the ffprobe-measured duration
(3.491020s), rather than trusting the printed rounded figures:

- `0.425 * 3.491020 ≈ 1.484s` — consistent with an actual elapsed time of
  ~1.48s, which rounds to the displayed `1.5s`. The displayed ratio
  (`0.425`) is computed from the unrounded elapsed/duration floats
  (`realtime_ratio` property), not from the rounded 1-decimal display
  strings (`1.5/3.5 = 0.4286`, which is a different, slightly-off number)
  — confirms the ratio isn't naively derived from the display strings.
- Target check: `target_seconds = duration_seconds / 2.0 = 3.491020 / 2 ≈
  1.746s`, which rounds to the displayed `1.7s`; `1.484s <= 1.746s` is
  true, matching the reported "within target" verdict.
- This is a real transcription (Whisper `tiny` model actually loaded and
  ran; stage announcements — `Extracting audio…`, `Transcribing…` with a
  progress percentage, `Writing subtitles…`, `Done.` — appeared on
  stderr), not a mocked/stubbed run.

**PASS.**
