### 3. Independently verified audio content: `clear_speech.mp4` non-silent, `silence.mp4` silent

Ran my own `ffmpeg` filter-based checks (not the PR's `wave`-based
amplitude helper in `test_conftest_fixtures.py` — a different method,
against the raw files):

**`volumedetect`** (measures actual mean/max dB across the whole audio
stream):

```
$ ffmpeg -i tests/fixtures/clear_speech.mp4 -af volumedetect -f null -
mean_volume: -21.0 dB
max_volume: -2.0 dB

$ ffmpeg -i tests/fixtures/silence.mp4 -af volumedetect -f null -
mean_volume: -91.0 dB
max_volume: -91.0 dB
```

`clear_speech.mp4` peaks at -2 dB (near full scale, i.e. clearly audible
content) with a -21 dB mean (consistent with speech, which isn't
continuously loud). `silence.mp4` measures a flat -91 dB for both mean and
max — ffmpeg's floor for a stream with no meaningful signal (i.e.
effectively digital silence throughout), not merely "quiet."

**`silencedetect`** (reports contiguous silent regions above a threshold):

```
$ ffmpeg -i tests/fixtures/clear_speech.mp4 -af silencedetect=noise=-30dB:d=0.5 -f null -
(no silence_start/silence_end events at all)

$ ffmpeg -i tests/fixtures/silence.mp4 -af silencedetect=noise=-30dB:d=0.1 -f null -
silence_start: 0
silence_end: 3.008 | silence_duration: 3.008
```

`clear_speech.mp4` produces zero silence events at a -30 dB threshold
across its entire 3.49 s — the audio stays audible for the full clip.
`silence.mp4` is reported as one continuous silent region spanning its
entire 3.0 s duration. Both independently-run filters (`volumedetect` and
`silencedetect`) agree with each other and with what the fixture/file
names claim. **PASS.**
