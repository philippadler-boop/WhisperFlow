## Requirement

> T027: Lint/type-check cleanup pass across `src/` and `tests/` (`ruff
> check --fix`).

The developer's finding was that `ruff check --fix` across `src/`,
`tests/`, `scripts/` found nothing to fix, so instead of a cleanup diff
the PR adds:

1. A regression test (`tests/unit/test_lint.py`) asserting `ruff check`
   and `ruff check --fix --diff` both come back clean across `src`,
   `tests`, `scripts`.
2. `ruff` declared as a `dev` optional-dependency in `pyproject.toml`,
   with a matching assertion in `tests/unit/test_pyproject.py`
   (`test_dev_dependency_ruff_declared`).

This decomposes into 6 checkable sub-requirements:

1. `ruff check src tests scripts` genuinely passes clean right now.
2. `pytest tests/unit/test_lint.py -v` passes right now.
3. The new test has teeth: a real, reversible lint violation injected
   into a real file under `src/` makes it fail with a clear message, not
   silently pass.
4. `ruff` is genuinely installed/importable in the environment `pytest`
   runs in, consistent with the new `pyproject.toml` dev-dependency
   declaration and `test_pyproject.py` assertion.
5. `tests/unit/test_pyproject.py` (including the new
   `test_dev_dependency_ruff_declared`) passes.
6. The broader suite (`pytest -q`) shows no regressions.

### 3. Fault injection — does the test actually have teeth?

**Step a — prove the violation triggers ruff, on a disposable file
outside the repo first**, per instructions, before touching anything in
the repo:

```
$ cat > <scratchpad>/scratch_lint_test.py
import os

def foo():
    return 1

$ python -m ruff check --select E,F,I,UP,B <scratchpad>/scratch_lint_test.py
I001 [*] Import block is un-sorted or un-formatted
F401 [*] `os` imported but unused
Found 2 errors.
```

Confirmed the chosen violation (an unused `import os`) genuinely
triggers ruff's `F401` (and incidentally `I001`) under this project's
selected ruleset before doing anything to the real repo.

**Step b — apply the same violation to a real file under `src/`.**
Confirmed clean working tree first (`git status --short` showed only a
pre-existing, unrelated untracked `docs/usr_tasks/`, present before this
session and untouched by this validation). Inserted `import os` (unused)
into `src/lib/errors.py` immediately after its existing `from __future__
import annotations` line:

```diff

+import os
```

not an artifact of the test itself:

**Note** (matches the reviewer's disclosed non-blocking nit): the

as a library but the `-m ruff` subprocess invocation somehow fails
independently, which was not observed here and is a pre-existing,
disclosed, non-blocking finding from review, not something this
validation newly discovered. **PASS.**
