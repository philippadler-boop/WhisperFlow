## Requirement

> Extend `reviewer-agent`'s prompt-building step to embed the fetched diff
> text into `reviewer`'s prompt (via the `prompt:` `with:`-field YAML
> substitution, never a `run:` shell splice) and instruct `reviewer` to use
> `Read`/`Grep`/`Glob` against the checked-out tree only for context beyond
> the diff, never to attempt re-deriving the diff itself, in
> `.github/workflows/claude-agents-pipeline.yml` (ADR 0005 Decision 3)

ADR 0005 Decision 3 (source of truth, cross-checked before validating):

> The `reviewer-agent` job's prompt-building step embeds that diff text
> verbatim into the prompt passed to `reviewer`'s `claude-code-action`
> invocation (via the `prompt:` `with:`-field, i.e. `${{
> steps.build_prompt.outputs.prompt }}` — a YAML-level substitution into an
> action input, not a `run:` shell splice ...), and instructs `reviewer` to
> use its `Read`/`Grep`/`Glob` tools against the checked-out working tree
> only for context beyond the diff, never to re-derive the diff itself (it
> has no tool capable of doing so reliably).

This decomposes into the following checkable sub-requirements:

1. A `Build prompt for reviewer` step (`id: build_prompt`) exists between
   `Fetch PR diff` and the `claude-code-action` step.
2. The diff arrives via `env: DIFF: ${{ steps.fetch_diff.outputs.diff }}`,
   referenced only as `"$DIFF"` in the shell script — never spliced via
   `${{ }}` directly into the `run:` script body.
3. Hostile diff content never executes, appears verbatim as inert data,
   and the `GITHUB_OUTPUT` structure isn't corrupted (the adversarial
   crux).
4. `claude-code-action`'s `prompt:` `with:`-field references
   `${{ steps.build_prompt.outputs.prompt }}` — a YAML-level substitution
   into an action input, not a `run:` shell splice.
5. The assembled prompt actually contains: the static instructional text,
   the diff embedded between markers, and explicit
   Read/Grep/Glob-for-context / do-not-rederive-the-diff instructions.
6. `tests/unit/test_reviewer_agent_prompt_wiring.py` (13 tests) genuinely
   pass, and the previously-vacuous heredoc test now has real teeth
   (independently reconstructed, not just re-read).
7. No regressions in the full suite (431 expected) or lint.

### 6. The previously-vacuous heredoc test — independently reconstructed, confirmed to have real teeth

Read `tests/unit/test_reviewer_agent_prompt_wiring.py` in full (298
lines). `test_build_prompt_never_places_diff_inside_a_fixed_heredoc` now
does `textwrap.dedent(_run_script_body(step_block))` before running
`re.finditer(r"cat <<(\S+)\n(.*?)^\1\s*$", run_body, re.M | re.S)` — the
fix the review round required, since the raw YAML text keeps the `cat
<<WORD ... WORD` heredoc content and its closing delimiter indented 10
spaces, which a column-0-anchored `^\1\s*$` never matches.

Independently reconstructed the regression this test exists to catch,
without touching the real repo file: copied the live workflow to the
scratchpad, then built a byte-modified variant
(`claude-agents-pipeline-BUGGY.yml`) with the `echo "$DIFF"` line moved
**inside** the `cat <<PROMPT_HEAD ... PROMPT_HEAD` heredoc (confirmed by a
`count()`-based assertion that exactly the T109 `echo "$DIFF"` occurrence
was removed, and T108's own unrelated `echo "$DIFF"` in `Fetch PR diff`
was left untouched).

Imported the **real** test module and called the **real** test function
directly against each file, by monkeypatching `WORKFLOW_PATH`:

```
=== Running the REAL test function against the ORIGINAL (fixed) file ===
PASSED (as expected for the correct implementation)

=== Running the SAME REAL test function against the BUGGY file (echo "$DIFF" moved inside cat<<PROMPT_HEAD) ===
FAILED as expected -- test correctly caught the regression:
  found $DIFF referenced inside a fixed-delimiter heredoc (<<PROMPT_HEAD) -- the diff must only be emitted via a standalone echo "$DIFF", never inside a heredoc whose delimiter is a fixed word a diff line could collide with
```

Separately reproduced the reported vacuousness for contrast, by running
the same regex **without** the `textwrap.dedent` step against both files:

```
--- ORIGINAL, NO DEDENT (reproducing the old vacuous test) ---
heredoc matches found: 0
--- BUGGY, NO DEDENT (reproducing the old vacuous test) ---
heredoc matches found: 0
```

Zero heredoc matches on both the correct and the buggy file confirms the
originally-reported failure mode exactly: without dedenting, the regex's
column-0 anchor never matches this step's 10-space-indented heredocs
regardless of whether the underlying bug is present, so the test's only
assertion never executes either way. With the dedent fix in place, the
same regex correctly distinguishes the two cases. This is an independent
reconstruction of the regression (a real modified file, the real test
function, run twice, both directions) — not a re-reading of the
developer's or reviewer's description of the fix. **PASS.**

## Delimiter randomization — environment note

Same caveat as T108's validation: this session is Git Bash/MSYS2 on
Windows, which lacks `/proc/sys/kernel/random/uuid`, so every run above
exercised only the `$RANDOM`-based fallback branch of `DELIM=...`, not the
primary uuid-based path that runs on the real `ubuntu-latest` Actions
runner. The fallback was observed producing distinct values across runs
(`PROMPT_EOF_151501397610072`, etc.), confirming it isn't a fixed string,
but the primary path is not independently verified here — disclosed as a
gap, not assumed to work by extrapolation.
