## Requirement

> T020: Implement the `--review` flow — write the draft `.srt`, invoke
> `$EDITOR`/`--editor`, wait for confirmation, re-read the file and mark
> changed lines' `edited` flag — in `src/cli/review.py` (depends on T005,
> T007) (data-model.md — `SubtitleLine.edited`; spec FR-009, FR-010)

Source documents cross-checked before validating:

- `spec.md` FR-009: "Users MUST be able to review the text of generated
  subtitle lines before treating the output as final."
- `spec.md` FR-010: "Users MUST be able to edit the text of individual
  subtitle lines, with edits reflected in the exported subtitle file."
- `data-model.md`: `SubtitleLine.edited` — "True once a user has changed
  `text` from its generated value; lets review tooling (FR-009)
  distinguish generated vs. corrected lines."
- `contracts/cli.md`: `--review`/`--no-review` opens the draft in
  `$EDITOR`/`--editor` and blocks until confirmation before finalizing;
  `--editor CMD` overrides `$EDITOR`/`$VISUAL`, else a built-in fallback
  prompt is used.

This decomposes into the following independently checkable
sub-requirements:

1. The draft `.srt` is actually written to disk **before** the editor (or
   fallback prompt) runs.
2. Editing a line's text in the draft actually flips that line's `edited`
   flag to `True` in the returned `SubtitleFile`, with the edited text
   reflected.
3. A line left untouched in the draft keeps `edited=False`.
4. A line added by the user in the editor (no original counterpart) is
   included in the result with `edited=True`.
5. A line removed by the user in the editor is absent from the result.
6. The no-editor fallback path (prompt + `confirm()`) works and reflects
   manual edits made before confirming.
7. Malformed/invalid content left in the draft raises `DraftParseError`
   rather than a raw library exception.
8. Windows editor-command path splitting (`_split_editor_command`) — the
   subject of one of the two review rounds — correctly handles a quoted,
   space-containing Windows path, an unquoted backslash path, and a
   multi-word command, both as a pure function and through a real
   subprocess launch.
9. `pytest tests/unit/test_review.py -v` and the full suite actually pass
   when run directly (not assumed from the PR description).
