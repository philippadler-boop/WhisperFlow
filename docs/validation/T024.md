### 2. Real fixture-video runs of README.md's documented examples/behaviors

All runs used `tests/fixtures/clear_speech.mp4` (copied to a scratch
directory outside the repo as `hello.mp4`), `--model tiny` (cached weights,
`HF_HUB_OFFLINE=1` — no network use, consistent with FR-004), against the
locally built venv's `whisperflow.exe`.

**a) Default-output-path example** (`whisperflow transcribe hello.mp4
--no-review`, README's first example):

```
Extracting audio…
Transcribing…
Transcribing…  91.7%
Writing subtitles…
Done.
EXIT: 0
```

`hello.srt` was written next to `hello.mp4` (not to a separate directory),
containing one subtitle block. Matches README's "The default output is next
to the input video" claim. **PASS.**

**b) Custom `-o`/`--output` path example**:
`whisperflow transcribe hello.mp4 --output .\output\hello.srt --model tiny
--no-review` (with `.\output\` pre-created) → exit 0, file written at
`output/hello.srt`. **PASS**, but see the directory-creation discrepancy
below.

**c) `--editor` review example** (README's `--editor "code --wait"`
pattern, substituted with a real, harmless, immediately-exiting Python
script standing in for a blocking editor): `--editor "python
C:/tmp/qa-t024/fake_editor.py"` → exit 0, finalized `.srt` written, no
fallback prompt shown (editor was actually invoked and blocked on, matching
"WhisperFlow waits for that process to exit"). **PASS.**

**d) No-editor-configured fallback prompt** (`$EDITOR`/`$VISUAL` unset, no
`--editor`, default `--review`): the real output was exactly

```
No editor configured (set $EDITOR/$VISUAL or pass --editor). Edit the draft
subtitle file at 'hello.srt' now, save it, then press Enter here to
continue…
```

then exit 0 after Enter — matching README's claim verbatim ("prints the
draft file's path and waits for you to press Enter after editing and saving
it yourself"). **PASS.**

**e) `$EDITOR` precedence and `--editor` override precedence**: with only
`$EDITOR` set to the harmless script, review ran without the fallback
prompt (confirms `$EDITOR` is honored). With `$EDITOR` set to a
nonexistent, guaranteed-to-fail command and a working `--editor` also
passed, the run still succeeded (exit 0) — confirming `--editor` takes
precedence over `$EDITOR`, matching the documented "The editor command
comes from `--editor`, falling back to the `$EDITOR` or `$VISUAL`
environment variable." **PASS.**

**f) Exit-code / error-message contract**: running against a deliberately
corrupt/unsupported input (`bad.mp4`, plain text content, not a real video
container) produced:

```
Error: could not determine a supported video format for 'bad.mp4'
(supported formats: mp4, mov, mkv)
EXIT: 1
```

with no `.srt` file left behind — matches README's Errors section ("Fatal
input and processing errors return exit code 1 and print one readable error
line to stderr... No partial subtitle file is left behind for input
validation failures"). **PASS.**

**Discrepancy found — README overclaims a directory-existence requirement.**
README.md's "Choose an output path" section states: *"Use `--output` or
`-o` to select the subtitle destination. **The destination directory must
already exist**"* (README.md line 66). This does not match real, observed
behavior: running `whisperflow transcribe hello.mp4 --output
.\nonexistent-dir\hello.srt --model tiny --no-review` against a directory
that did **not** exist beforehand succeeded (exit 0) and the directory was
created automatically. Confirmed in source as well —
`src/subtitles/models.py`, `SubtitleFile.write()`:

```python
def write(self, path: Path | None = None) -> Path:
    """Compose `lines` and write the result to `output_path` (or `path`).

    Creates parent directories as needed. Returns the path written to.
    """
    target = Path(path) if path is not None else self.output_path
    if target is None:
        raise ValueError("SubtitleFile.write requires an output_path (none set)")
    target.parent.mkdir(parents=True, exist_ok=True)
    ...
```

`contracts/cli.md` makes no claim either way about directory existence, so
this isn't a contract/implementation divergence — it's a README claim that
is simply incorrect against the real, observed and source-confirmed
behavior. **This is a genuine documentation inaccuracy introduced by T024**
(the sentence isn't present in `contracts/cli.md` at all — it appears to be
added editorial text that doesn't match reality). **FAIL** on this specific
claim.

## Overall: FAIL (documentation contains one confirmed inaccuracy)

Every mechanical and behavioral claim in README.md's `transcribe`
documentation was independently verified against the real, installed CLI
and real fixture-video runs, and matches — including several precise
behavioral claims (fallback-prompt wording, editor precedence order, exit
codes, error-message shape) that could easily have drifted from the
contract without a test catching it. The guarding test suite genuinely has
teeth after the review-round fix: both previously-weak assertions were
independently confirmed to fail against broken content that the old,
substring-only versions would have let through.

However, one concrete, observable discrepancy was found: README.md's
"Choose an output path" section states "The destination directory must
already exist," but the real CLI (confirmed both by running it and by
reading `SubtitleFile.write()` in `src/subtitles/models.py`) creates
missing parent directories automatically via `target.parent.mkdir(parents
=True, exist_ok=True)`. This claim is not present in `contracts/cli.md` (so
it isn't a contract-vs-implementation divergence) — it appears to be
inaccurate editorial text added directly in the README during T024, and no
test in `tests/unit/test_readme_docs.py` currently guards this specific
claim (it doesn't assert on the "must already exist" sentence). Per this
task's instruction to flag "any discrepancy however small," this is
reported as a failing sub-requirement rather than folded into an otherwise
clean pass. Recommend either removing/correcting the sentence, or (if the
mkdir-on-write behavior is itself unintended production behavior deserving
its own scrutiny) filing it as a follow-up — but per QA's role, that fix is
left to the implementation, not made here.
