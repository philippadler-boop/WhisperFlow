## Requirement

Per `data-model.md`, `SubtitleLine.edited`: "True once a user has changed
`text` from its generated value; lets review tooling (FR-009) distinguish
generated vs. corrected lines." Per spec.md:

- **FR-009**: Users MUST be able to review the text of generated subtitle
  lines before treating the output as final.
- **FR-010**: Users MUST be able to edit the text of individual subtitle
  lines, with edits reflected in the exported subtitle file.

T023's target file `tests/unit/test_review.py` predates this PR (added
under T020's PR alongside `src/cli/review.py`, with a
`TestReviewSubtitleFileEditedFlag` class already covering the core rule:
single-line edit flags only that line, and a no-op re-save leaves `edited`
alone). This PR does not implement new production code — it adds three
non-redundant unit tests to close gaps in that existing coverage:

1. `test_multiple_edits_flag_only_the_changed_lines` — with three lines and
   two simultaneous edits, confirms only the changed lines get
   `edited=True`, not every line once any line changes.
2. `test_edits_are_matched_by_index_not_by_position` — confirms a reordered
   draft still attributes edits to the correct line by `SubtitleLine.index`
   rather than by file position.
3. `test_reediting_an_already_edited_line_to_new_text_updates_text_and_stays_edited`
   — confirms editing an already-`edited=True` line to yet more new text
   updates `text` and keeps `edited=True`.

Because this task only adds tests, "validating T023" means confirming the
new tests genuinely exercise the claimed behavior and would catch a real
regression in `_reread_with_edits`/`with_text`, not just that pytest
reports green.

### 2. Full `tests/unit/test_review.py` read, three new tests confirmed to match their claims

Read in full (444 lines). The three new tests (lines 155–247) each
directly correspond to the mechanism above:

- `test_multiple_edits_flag_only_the_changed_lines` builds a 3-line file,
  edits lines 1 and 3 via the fake editor, and asserts
  `[edited, not edited, edited]` — genuinely exercises independent
  per-line tracking beyond the pre-existing 2-line fixture.
- `test_edits_are_matched_by_index_not_by_position` writes the draft with
  blocks in **swapped order** (index 2 first, index 1 second), edits only
  what was originally index 2, and asserts by index (not position) that
  index 1 stayed unedited/unchanged and index 2 got the edit — this is a
  direct, targeted test of the index-vs-position matching behavior
  documented in `_reread_with_edits`'s own docstring.
- `test_reediting_an_already_edited_line_to_new_text_updates_text_and_stays_edited`
  starts a line at `edited=True` with text "First correction.", edits it
  again to "Second correction.", and asserts both the text update and that
  `edited` stays `True` — exercises `with_text()`'s branch where the prior
  `edited` value is already `True` and the text does change (as opposed to
  the pre-existing `test_resaving_an_already_edited_line_unchanged_keeps_edited_true`,
  which covers the same starting state but with no text change).

All three are non-redundant with the pre-existing
`TestReviewSubtitleFileEditedFlag` tests. **PASS** (tests match their
stated claims).

### 4. Teeth check — deliberately broke index-based matching, confirmed the intended test (and only that one) fails

assertion teeth rather than passing vacuously, `_reread_with_edits` in the
actual repo file `src/cli/review.py` was temporarily edited in place to
replace index-based dict lookup with naive positional matching:

```diff
     new_lines: list[SubtitleLine] = []
     try:
-        for entry in parsed:
-            original = originals_by_index.get(entry.index)
+        for position, entry in enumerate(parsed):
+            # BROKEN ON PURPOSE (QA teeth-check): naive positional matching
+            # instead of index-based dict lookup.
+            original = (
+                subtitle_file.lines[position] if position < len(subtitle_file.lines) else None
+            )
             if original is not None:
```
