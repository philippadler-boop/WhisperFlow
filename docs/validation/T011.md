## Requirements

The source-of-truth requirements were read directly from
`specs/001-video-subtitle-generator/spec.md` and
`specs/001-video-subtitle-generator/data-model.md`:

- **FR-002**: produce a time-synchronized transcript in the video's original
  source language.
- **FR-004**: perform transcription locally; video/audio content must not be
  transmitted to a cloud or third-party service.
- **FR-008**: clearly report no detectable speech rather than failing or
  producing misleading output. For T011, the data-model contract expresses
  this as a successful `Transcript` with an empty `segments` list; the
  user-facing notice is owned by the later T013 pipeline.

## Evidence

### 1. Real clear-speech transcription — FR-002

Executed `probe_video()`, `extract_audio()`, and `transcribe_audio()` against
`tests/fixtures/clear_speech.mp4` using the real `WhisperModel('tiny',
device='cpu', compute_type='int8')`, with no model or transcription mock.
The observed output was:

```text
MODEL_LOADED=tiny/cpu/int8
clear_speech.mp4: type=Transcript language='en' segments=1
  segment start=0.000 end=3.200 text='Hello, this is a test on the whisper flow sub-title generator.'
REAL_FIXTURE_TRANSCRIPTION=PASS
```

The result was a genuine `Transcript`, its detected language was English, it
contained a non-empty timed segment, the segment had positive duration, and
the recognized text contained the expected word `test`.

**PASS** — T011 produces a source-language transcript with sensible text and
non-zero timing from a real extracted audio track.

### 2. Real silence transcription — FR-008

The same real-model command processed `tests/fixtures/silence.mp4` and
observed:

```text
silence.mp4: type=Transcript language='nn' segments=0
REAL_FIXTURE_TRANSCRIPTION=PASS
```

`transcribe_audio()` returned normally with a `Transcript` and an empty
`segments` list; no transcription exception was raised. The later pipeline's
human-readable "no speech detected" notice is not implemented by T011 and
was not assessed here.

**PASS** — T011 represents no detectable speech as a successful empty
transcript, as required by the data model and FR-008.

### 3. Local-only processing — FR-004

After loading the real tiny model locally, the validation command extracted
the clear-speech fixture and replaced `socket.socket.connect` with a guard that
would fail the run on any outbound socket connection during
`transcribe_audio()`. The observed output was:

```text
LOCAL_ONLY_TRANSCRIPTION=PASS segments=1
```

The model was constructed and executed in-process with `device='cpu'`; the
transcription completed while outbound socket connections were blocked.

**PASS** — the exercised transcription path processed the local audio without
an outbound connection. The one-time model load occurred before the network
guard, so model-weight acquisition was not confused with per-video
transcription.

### 4. Callback and ASR failure behavior — T011 error contracts

A fresh inline scenario supplied a model whose segment callback raised
`LookupError`, and a separate model whose `transcribe()` raised
`RuntimeError`. The observed output was:

```text
CALLBACK_EXCEPTION=LookupError: callback probe failure
ASR_EXCEPTION=TranscriptionError: failed to transcribe audio from '.../probe.wav': decoder probe failure
FAILURE_CONTRACTS=PASS
```

The callback exception propagated as its original type rather than being
misattributed to the ASR engine. The genuine ASR failure was converted to
`TranscriptionError` and retained its reason.

**PASS** — the reviewed callback regression is fixed, while ASR-level
failures remain normalized to the domain error.

### 5. Invalid model configuration — model-load error contract

The validation command called `transcribe_audio()` with the invalid model
size `__not_a_real_faster_whisper_model__`. The real library rejected it and
T011 exposed:

```text
MODEL_EXCEPTION=ModelLoadError: failed to load ASR model '__not_a_real_faster_whisper_model__': Invalid model size '...'
FAILURE_CONTRACTS=PASS
```

**PASS** — an unloadable model configuration raises `ModelLoadError` rather
than leaking the library exception.
