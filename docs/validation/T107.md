## Requirement

> T107 [US1] Add a `Checkout PR head` step to `reviewer-agent`, checking
> out `github.event.pull_request.head.sha` (not `main`, not a bare
> default-branch checkout) in `.github/workflows/claude-agents-pipeline.yml`
> (ADR 0005 Decision 1)

ADR 0005 Decision 1 (source of truth, cross-checked before validating):

> **Checkout**: a `Checkout repository` step in the `reviewer-agent` job
> checks out the PR's own head branch at its current `head.sha` (not
> `main`, and not a bare `fetch-depth: 1` of the default branch), so
> `reviewer`'s `Read`/`Grep`/`Glob` calls resolve against the PR's actual
> current file tree ... `actions/checkout@v7` and `fetch-depth: 1` mirror
> `dev-agent`'s own checkout step above for consistency.

This decomposes into the following checkable sub-requirements:

1. The live workflow file contains a `Checkout PR head` step in the
   `reviewer-agent` job.
2. That step is positioned **before** the `claude-code-action` step in the
   same job.
3. `with.ref` is exactly `${{ github.event.pull_request.head.sha }}` — not
   `main`, not omitted (which would default-checkout the base branch).
4. `uses: actions/checkout@vN` matches the same version `dev-agent`'s own
   checkout step uses, per ADR 0005's explicit "mirror `dev-agent`"
   instruction.
5. `tests/unit/test_reviewer_agent_checkout_pr_head.py` genuinely passes.
6. No regressions in the full suite (405 tests) or lint.

## Evidence

### 1 & 2. Step exists, positioned before `claude-code-action`

Read `.github/workflows/claude-agents-pipeline.yml` in full (498 lines).
The `reviewer-agent` job's `steps:` list (lines 366–420) is:

```yaml
    steps:
      - name: Checkout PR head
        uses: actions/checkout@v7
        with:
          ref: ${{ github.event.pull_request.head.sha }}
          fetch-depth: 1

      - name: Run Claude Code (reviewer agent, unattended)
        uses: anthropics/claude-code-action@v1
        ...
```

Confirmed independently via a real PyYAML parse (not just a text read),
`python3 -c "import yaml; ..."`:

```
reviewer-agent step order: ['Checkout PR head', 'Run Claude Code (reviewer agent, unattended)']
```

The checkout step is the first (index 0) of exactly two steps, and the
`claude-code-action` step is second (index 1). **PASS** on both 1 and 2.

### 3. `ref:` is exactly `${{ github.event.pull_request.head.sha }}`

From the same parsed structure:

```
checkout step: {'name': 'Checkout PR head', 'uses': 'actions/checkout@v7',
'with': {'ref': '${{ github.event.pull_request.head.sha }}', 'fetch-depth': 1}}

```

The parsed dict's `with.ref` value is the literal string
`${{ github.event.pull_request.head.sha }}` — verified by direct string
equality assertion (`assert checkout['with']['ref'] ==
'${{ github.event.pull_request.head.sha }}'`, which raised no
`AssertionError`), not a substring or regex match. No `ref: main` and no
absence of `ref:` (which would fall back to checking out the event's
default/base ref) is present anywhere in the step. **PASS.**

### 4. `actions/checkout` version matches `dev-agent`'s own checkout step

Read both steps directly:

- `dev-agent`'s "Checkout repository" step (lines 81–84):
  `uses: actions/checkout@v7`, `with: { fetch-depth: 1 }` (no `ref:`,
  correctly defaulting to the triggering ref for that job's own use case).
- `reviewer-agent`'s "Checkout PR head" step (lines 381–385):
  `uses: actions/checkout@v7`, `with: { ref: ${{ github.event.pull_request.head.sha }}, fetch-depth: 1 }`.

Parsed-structure comparison:

```
dev-agent checkout step: {'name': 'Checkout repository', 'uses': 'actions/checkout@v7', 'with': {'fetch-depth': 1}}
checkout uses match: True
```

Both pin `actions/checkout@v7` exactly, and both set `fetch-depth: 1` —
matching ADR 0005's explicit instruction to mirror `dev-agent`'s existing
pattern. **PASS.**
