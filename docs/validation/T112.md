## Requirement

> T112 (`specs/002-reviewer-qa-automation/tasks.md`): Add a step to
> `reviewer-agent`'s job, immediately after the existing "Run Claude Code
> (reviewer agent, unattended)" step (`id: run_reviewer`), that obtains a
> non-default GitHub identity for later posting the review (ADR 0007
> Decision 1): captures `steps.run_reviewer.outputs.github_token`, fails
> visibly if empty, masks it, and re-exposes it as its own `token` output.
> Does not itself post any review (T113's scope).

This decomposes into the following checkable sub-requirements:

1. The new step exists in the live workflow file, `id:
   get_review_identity`, positioned immediately after `run_reviewer`.
2. It references `steps.run_reviewer.outputs.github_token` (not
   `${{ github.token }}` or any other default-token source).
3. It fails visibly (non-zero exit) when that value is empty, rather than
   silently falling back to a default token (FR-013).
4. It masks the token (`::add-mask::`) before writing it to
   `$GITHUB_OUTPUT`.
5. It exposes the token as its own `token` output.
6. It does not itself call `gh pr review` or post anything (scope
   boundary with T113).
7. The task's three named test files pass with zero skips.
8. No regressions in the full test suite.
9. `ruff check .` is clean.
10. The PR body contains a correctly-formed `Closes #149` line.
11. CI is green on PR #185.
12. Explicitly flagged: the claim that `claude-code-action@v1`'s
    `action.yml` exposes a `github_token` output is a third-party fact
    this session cannot independently verify (no web access) — must be
    disclosed as an accepted, unverified-but-not-blocking gap, not
    silently treated as confirmed.

```
674:      - name: Obtain non-default GitHub identity for posting the review
675:        id: get_review_identity
676:        env:
677:          REVIEW_TOKEN: ${{ steps.run_reviewer.outputs.github_token }}
678:        run: |
679:          if [ -z "$REVIEW_TOKEN" ]; then
```

step is interposed. It reads `steps.run_reviewer.outputs.github_token`,
exactly the output the `run_reviewer` step's `id` makes addressable. **Pass.**

### 12. The one claim this session cannot independently verify

ADR 0007 Decision 1 and this PR's own description assert that
`anthropics/claude-code-action@v1`'s `action.yml` declares a first-class
`github_token` output (surfacing the Claude GitHub App's own token when
the step's `github_token` input is omitted, as `run_reviewer` already
does). **This session has no web access and cannot fetch or inspect that
third-party action's `action.yml` to confirm this claim.** Nothing in this
repository can independently corroborate a third-party GitHub Action's
actual output contract — this is not a gap that can be closed by grepping
this codebase harder.

This is explicitly **not** treated as a blocking failure, for a reason
this task's own design already accounts for: if the claim is false (the
action does not actually expose that output, or it is empty at runtime),
`steps.run_reviewer.outputs.github_token` would simply be empty or absent
at real workflow execution time, and the empty-check proven in section 5
above fires — the job fails **loudly** (`::error::` + `exit 1`) rather than
silently falling back to the default `GITHUB_TOKEN` or posting anything
under an ambiguous identity. That fail-loud behavior is exactly what
FR-013 requires and is the mechanism by which a false claim here becomes
visible and diagnosable on the very first real `reviewer-agent` run,
rather than an assumption this report is asked to rubber-stamp. This gap
is disclosed rather than silently accepted as confirmed, per Constitution
Principle V.
